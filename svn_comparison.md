# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?
В Git ветка — это просто файл с 40-символьным хешем коммита (указатель). Создание ветки — запись одного файла, мгновенно и локально, без копирования данных. В SVN ветка создаётся как копия каталога (`svn copy trunk branches/x`) на центральном сервере: это сетевая операция, она создаёт новую ревизию для всех, а слияние веток исторически было ручным и плохо отслеживало, что уже влито. Поэтому в SVN веток избегали, а в Git их создают под каждую задачу.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?
Нет. SVN — централизованная система: история хранится только на сервере, а у разработчика есть лишь рабочая копия одной ревизии. Коммит — это отправка изменений на сервер, который присваивает номер ревизии. Без связи с сервером можно только редактировать файлы и смотреть локальный diff. В Git коммит пишется в локальный репозиторий, на сервер он уходит позже через `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?
- **Большие бинарные файлы** (игровые ассеты, CAD-модели, видео): SVN позволяет выкачать только нужный подкаталог и последнюю ревизию, а не всю историю.
- **Блокировки файлов** (`svn lock`): для файлов, которые нельзя смержить (Photoshop, Excel), нужен эксклюзивный доступ.
- **Жёсткий централизованный контроль доступа** вплоть до отдельных каталогов — часто требуется в госсекторе и банках.
- **Legacy-проекты** с многолетней историей и инфраструктурой, завязанной на номера ревизий.
