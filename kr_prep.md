# Подготовка к КР

## Когда я выберу rebase, а когда merge? Почему?
Rebase — для своей локальной (ещё не опубликованной или только моей) feature-ветки, чтобы подтянуть свежий main и получить линейную историю перед PR. Merge — для интеграции в общие ветки (main, release), когда важно сохранить факт параллельной разработки и не переписывать уже опубликованные коммиты.

## Что произойдёт, если я сделаю rebase публичной ветки, с которой работают коллеги?
Rebase создаёт новые коммиты с новыми хешами. У коллег останутся старые коммиты, их ветки разойдутся с удалённой: `git pull` создаст дубли коммитов и конфликты, а push без `--force` будет отклонён. Принудительный push может уничтожить чужую работу.

## Зачем нужен multi-remote и в каких реальных сценариях он применяется?
Чтобы один локальный репозиторий синхронизировался с несколькими серверами: зеркало/резервная копия на другом хостинге (GitHub + GitLab), работа с fork (origin — свой fork, upstream — оригинальный проект), миграция между платформами, отдельный remote для деплоя (например, Heroku/Dokku).
